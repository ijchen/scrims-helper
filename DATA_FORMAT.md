# Scrims Helper data format — v1

V1 is the first supported public format. Prerelease browser saves and exports
are intentionally unsupported. Future incompatible changes require explicit
versioning and a supported upgrade path for public v1 data.

## Browser storage

All application data is JSON in localStorage under `scrims-helper.state`:

```json
{
  "format": "scrims-helper-state",
  "version": 1,
  "players": [],
  "scrims": [],
  "activeScrimId": "...",
  "mapPoolPresets": [],
  "customGameCode": ""
}
```

This illustrates the envelope, not a complete valid save: there must be at
least one scrim, and activeScrimId must identify it. Switching scrims changes
that pointer, not the contents or order of the list.

Theme and divider position are separate localStorage entries,
`scrims-helper.theme` and `scrims-helper.panelSplit`. They are device-local and
never included in exports. There is no server-side storage or synchronization.

## Records

All fields below are required unless explicitly marked optional. Unknown
fields are rejected. Validation checks without modifying input or supplying
defaults. New records receive defaults when created, not when loaded.

Identifiers generated by the app are UUIDs. They are opaque, case-sensitive
strings to readers; imports match IDs, never names or BattleTags. IDs must be
unique within each entity list, and game IDs within each scrim (including its
active game).

### Player directory

Each player has:

| Field | Value |
| --- | --- |
| id | Persistent player ID |
| name | Nonblank display name |
| battletag | BattleTag, or empty string |
| roles | Main roles: unique subset of Tank, HSDPS, FDPS, MS, FS |
| offRoles | Optional unique subset of those same slots, disjoint from roles; omitted means no declared fills |
| status | default, trial, team, or ringer |
| notes | Plain text, or empty string |

An empty roles list is valid, including for fill-only players. offRoles is an
additive v1 field; earlier v1 saves remain valid without it. Preferences classify
historical assignments at scheduling time: current main roles earn preferred
playtime credit; all other assignments count as fills. No classification snapshot
is stored, so changing preferences recalculates scheduling credit and fill burden.
Actual game counts remain unchanged. Role groups used for statistics are derived:
Tank → tank; HSDPS/FDPS → DPS; MS/FS → support.

### Scrims

Each scrim has `id`, `createdAt` (ISO timestamp, or empty when not yet
initialized), and `session`. Session contains:

| Field | Value |
| --- | --- |
| title | Scrim name, possibly empty |
| contact | Contact BattleTag, possibly empty |
| attendees | Unique { playerId, present } entries |
| lineup | Object with Tank, HSDPS, FDPS, MS, FS keys |
| draft | Upcoming { map, mode, ourBan, theirBan } |
| activeGame | Game record, or null |
| games | Completed game records, oldest first |
| disabledMapIds | Unique map IDs excluded for this scrim |
| bansEnabled | Optional boolean; omitted means true. False hides bans and records new games without bans; existing records are preserved. |

Attendees reference existing directory players. Lineup values are attendee
player IDs or empty strings for unfilled slots; players cannot appear twice.
Absent and off-role assignments are allowed in the planned lineup.

### Games

Games contain `id`, `map`, `mode`, `ourBan`, `theirBan`, `outcome`,
`playedAt`, `lineup`, and optional `startedAt`.

- outcome: win, loss, draw, or empty if not recorded.
- playedAt: ISO completion timestamp; while active, initially the start time.
- startedAt: ISO start timestamp, required for an active game.
- lineup: exactly five { role, playerId, name, battletag } snapshots,
  one per slot, without duplicate players.

Historical snapshots need not reference a player still in the directory.
Renaming or deleting a directory player does not rewrite recorded names,
BattleTags, or role assignments. Upcoming, active, and completed records
are separate snapshots rather than shared mutable references.

Game counts, role counts, W/L/D totals, conflicts, and mode rotations are
calculated from game records, not stored as redundant counters.

### Map and hero references

`map`, `ourBan`, and `theirBan` are null when unset, otherwise:

```json
{ "id": "ana", "name": "Ana" }
```

Known entries use catalog IDs; custom entries use an empty ID and a nonblank
name. Unknown/removed IDs remain valid. The saved name preserves readable
history; asset lookup uses the ID, not a guess from the name. Images are
bundled app assets, not embedded in saves.

Mode is recorded separately: Control, Push, Hybrid, Escort, Flashpoint, or
empty if unspecified. Its saved value preserves the historical selection.

### Shared settings

Map pool presets are { id, name, mapIds }, with nonblank names unique after
trimming and case-folding. mapIds contains unique enabled catalog IDs; unknown
IDs are preserved. Applying a preset copies its selection into a scrim.
An empty preset enables no maps; an empty disabledMapIds list enables all maps.
New catalog maps are enabled unless explicitly disabled for that scrim.

customGameCode is shared across scrims; blank/whitespace uses the app default
(currently DKEEH).

## Exports

```json
{
  "format": "scrims-helper-export",
  "version": 1,
  "schema": "scrims-helper-v1",
  "data": {
    "players": [],
    "mapPoolPresets": [],
    "customGameCode": ""
  }
}
```

The schema marker is required: prerelease exports also used version 1, and
even a players-only prerelease export must not be confused with public v1.

data includes only selected categories, with at least one present:
players, scrims, mapPoolPresets, customGameCode. Scrims are represented as
`{ activeId, items }`, where items uses the same scrim records as browser
storage. A scrim export must include players. Preferences are not categories.
Raw browser-state objects are not accepted as export files.

An omitted category means “not included,” never “clear this category.”
An included empty array can deliberately clear a replaceable collection.
An included blank customGameCode resets it to the app default.

Import offers Replace/Merge/Skip for lists and Replace/Skip for the code.
Merge replaces matching IDs and retains unrelated IDs. Scrim merge keeps
the current active scrim; replacement uses the imported activeId.
Scrims cannot be imported while skipping players. Replacing players requires
replacing scrims or explicitly clearing existing scrims, never retaining
potentially dangling references. Conflicting preset names are rejected.
The complete proposed state is validated before any write.

## Validation and failure behavior

The executable contract is in schema.js and backups.js. Current limits:
1,000 players/attendees; 100 scrims/presets; 10,000 completed games per scrim;
1,000 map IDs per list. Strings are bounded to 100 characters unless noted:
player/preset names 80, notes 500, custom code 20. File import is limited to
10 MiB. Limits apply to the merged result as well as imported data.

Unsupported or malformed saves are never silently rewritten. A blocking
dialog offers Start fresh or Import backup. Escape and backdrop clicks do
not dismiss it. Canceling or failing an import preserves the original data.
Start fresh explicitly clears app data/preferences; applying a valid import
replaces the unreadable saved state only after confirmation.

Old storage key detection exists solely to show this reset path, not to
convert or support old formats. Reset also removes known prerelease keys.
Other-tab changes pause writes until reload.
